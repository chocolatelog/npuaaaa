# 通用神经网络处理器下的多核调度问题——求解方法与结果报告

本目录为 2026 年研究生数模竞赛 A 题（华为）"通用神经网络处理器下的多核调度问题"的
求解结果。算法代码位于 `solver/`，求解产出的调度方案位于 `results/plans/`，
官方评估器评估结果位于 `results/official/`，汇总见 `results/summary.csv`、
`results/summary.md` 与 `results/plots/`。

## 1. 问题建模

**决策变量**（与题目定义一致）：

1. 切图：每个核内操作节点（非 COPY_IN/COPY_OUT）到子图 id 的映射；
2. 分核：每个子图到核心的分配；
3. 排序：每个核心上子图的执行顺序（不得违反子图依赖）。

**合法性关键结论**：DAG 的任意划分得到的子图商图**未必无环**（子图沿路径交错时
商图成环），因此方案必须满足"子图依赖图为 DAG"。本求解器在块图与解上均实现了
Tarjan SCC 缩聚修复，保证产出的方案恒为合法。

**目标**：主目标 Makespan（官方模拟器给出），次目标总额外数据搬运量。
两目标通过标量化 `f = Makespan + w·AddedBytes/60`（w=0.2，把字节折算成
60 B/cycle 带宽下的周期数）与 Pareto 归档同时处理（多目标优化框架）。

## 2. 求解框架

```
计算图 JSON
   │
   ├─ 预处理：收缩 COPY_IN/COPY_OUT 得 op 级 DAG；
   │   沿最高流量前驱做路径式块粗化（块=搜索原子，粒度≈400op/块上限夹在[24,240]）；
   │   块商图 SCC 缩聚保证块 DAG 无环
   │
   ├─ 快速代理评估器（搜索内循环，~2-20ms/次）
   │   · 新增搬运量：按官方边界 COPY 插入规则逐 tensor 精确计算（与评估器逐字节一致）
   │   · Makespan 估计：子图时长 = max(Cube 负载, Vector 负载, 入搬运/60, 出搬运/60,
   │     子图内部串行关键路径)；事件仿真派生每核顺序（拓扑合法）并叠加
   │     Task 等待（场景A 100/1000cyc）或跨核同步（场景B 500cyc）；
   │     L1/UB 双池驻留峰值超限 + 内部总字节超限 → spill 惩罚；
   │     全部搬运量/60 作为全局带宽下界
   │
   ├─ 构造式初始解池：HEFT 风格块调度（5 种子图规模）× 拓扑条带（3 种）× 链式 LPT
   │
   ├─ 元启发式改进（共享 Pareto 归档）
   │   ① 禁忌搜索：邻域采样 + 属性禁忌 + 渴望准则
   │   ② 模拟退火：几何降温 + 混合邻域（随机 + 通信边界定向）+ 重启
   │   ③ 蚁群：信息素挂在 (块,簇归属/核) 决策上，蚂蚁沿拓扑序构造，精英沉积
   │   ④ 多目标粒子群（MOPSO）：随机键编码（每块 cut/pref 两基因 + 全局 K 基因），
   │     解码为凸切分+分核；基因空间 Pareto 前沿 + 拥挤距离选领袖
   │
   └─ 最终选择：候选 = 搜索最优 ∪ 归档标量最优 ∪ 构造池前三；
       ≤1.2 万 op 的用例用官方评估器（进程内调用）真值校验后选优
```

## 3. 各算法要点

### 3.1 邻域动作（禁忌搜索 / 模拟退火共用）

- `move_block`：把块移入另一子图（定向版优先选跨子图高流量边上的块）；
- `move_core`：子图换核；
- `merge/split`：子图合并 / 按拓扑序中位拆分（自适应子图数）；
- `swap_block`：交换两块的子图归属。

### 3.2 禁忌搜索

每代采样 12 个邻居取最优可行（禁忌属性=动作对象，任期≈0.6√块数，
渴望准则=优于历史最优），直到时间预算耗尽。

### 3.3 模拟退火

初温=0.15×当前适应度，几何降温 0.995，接受劣解概率 exp(-Δ/T)；
50% 概率使用通信边界定向邻域；收敛后从最优解扰动重启。

### 3.4 蚁群

蚂蚁沿块拓扑序构造：对每块在"新建簇 / 并入最近 m=6 个开簇"间按
信息素×启发式（通信亲和度、负载均衡）轮盘赌选择，新建簇时再按
（信息素×局部性+均衡）选核；构造后直接评估；每代前 1/3 精英按
1/(1+rank) 权重沉积信息素，蒸发率 0.15。

### 3.5 多目标粒子群（MOPSO）

粒子=2·块数+1 维连续向量：cut 基因取拓扑序上最大的 K-1 个位置为切点
（凸划分，商图必无环），pref 基因在分核时按票数偏置最早完成选择，
全局基因 g 决定目标子图数 K∈[Kmin,Kmax]。速度更新含惯性/个体最优/
领袖项，领袖从基因空间 Pareto 前沿按拥挤距离轮盘赌选取。
所有算法向共享 ParetoArchive 供解，形成多目标优化整体框架。

全部 100 个测试用例、2~5 核、三个问题均由赛题官方评估器（固定 config.txt）完成评估，
评估全部成功（无非法方案）。**平均加速比**（单核基准 = 核内调度算法在整图上的
Makespan，单核加速比定义为 1）：

| 核数 | 问题 1（场景 A） | 问题 2（场景 B） | 问题 3（场景 B + L2） |
|---|---|---|---|
| 1 | 1.000 | 1.000 | 1.000 |
| 2 | 1.735 | 1.729 | 1.745 |
| 3 | 2.241 | 2.351 | 2.386 |
| 4 | 2.623 | 2.851 | 2.924 |
| 5 | 2.989 | 3.261 | 3.366 |

（经三轮单调改进协议后的最终版；首版分别为 P1 1.675/2.150/2.529/2.812、
P2 1.704/2.315/2.802/3.162、P3 1.721/2.354/2.874/3.267。）
曲线见 `plots/speedup.png`。逐用例 Makespan 与总额外搬运量见 `appendix.md` 与
`summary.csv`。

**问题 3 只读 L2 Cache 相对无 L2 基线的加速比**（同一方案在 P2/P3 评估器下的 Makespan
之比，`plots/l2_speedup.png`）：

| 核数 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|
| L2 加速比 | 1.0095 | 1.0139 | 1.0260 | 1.0346 |

L2 平均 Cache 命中率 14.6%（中位数 9.3%），且核数越多收益越大（2 核 +0.9% →
5 核 +3.7%）——与"L2 复用多核共享输入、核越多重复读取越多"的机制一致。

**问题 2 相对问题 1 的提升**（同核数下场景 B 利用同核 L1/UB 数据驻留）：
2 核 +1.7%、3 核 +7.7%、4 核 +10.8%、5 核 +12.4%，验证了"强依赖子图同核放置 +
核内复用"策略的有效性。

**分布特征**（4 核问题 2）：中位数 3.08×，最高 4.48×（case_059，宽并行图）；
个别深串行图（case_016，深度 2441 的单链结构）加速比≈1，属图结构固有串行性。
宽并行图接近线性加速，深窄图受关键路径与跨核同步限制，符合问题机理。

## 5. Mamba 式 SSM 轻量代理评估器（候选解粗筛层）

为降低邻域扰动中的完整仿真次数，在 SA/TS 内环引入 Mamba(S6) 风格的
选择性状态空间模型作为轻量代理（`solver/mamba_screen.py`）：

- **结构**：输入依赖门控的离散化递推 h_t = a(x)⊙h_{t-1} + b(x)，
  a/b 由固定随机投影 + sigmoid/tanh 生成（selective）；读出层
  ŷ = w·[h_t; x] 由 NLMS 在线学习（每次完整仿真得到真值标签后即时更新，
  无离线训练）。特征为 16 维廉价移动特征（动作类型、块工作量/流量、
  目标子图亲和度、核负载均衡、当前适应度上下文等），单次预测仅数百次乘加。
- **用法（锦标赛式软筛选，仅作用于 SA）**：每步生成 4 个候选扰动，
  全部先做 SSM 预测，仅对预测最优者（ε=15% 概率换随机者，用于漏筛率
  估计与训练数据补充）执行完整仿真；决策仍始终基于真值适应度，
  避免"预测即接受"污染搜索状态。
- **A/B 对照**（12 代表用例 × 场景 A/B × 4 核，隔离实验：构造→TS→SA，
  同种子，等完整仿真预算 1500 次）：

  | 配置 | 平均 Makespan 变化 | 结果 |
  |---|---|---|
  | 等预算（筛选 1500 vs 基线 1500） | **-0.87%** | 4 优 / 20 平 / **0 负** |
  | 60% 预算（筛选 900 vs 基线 1500） | +1.27% | 17/24 用例退化 <1% |

  即：**同等质量下可削减约 40% 完整仿真次数**（代价 <1.3% 均值），
  或**同等仿真预算下搜索空间探索多 ~4 倍**（SA 内 75% 候选跳过完整仿真，
  质量持平略优，困难用例获益显著：case_044 场景A -17.9%）。
- **设计取舍**：TS 的锦标赛粗筛会改变禁忌动态（每代真值评估变少 +
  迭代速率改变导致任期相对变短），在部分用例上劣化，故最终配置仅在
  SA 启用；生产流水线默认关闭该层（`use_screen=False`）以最大化最终
  质量，作为搜索加速选项提供（`pipeline.solve_case(..., use_screen=True)`）。

## 6. 自主优化轮次（spill 校准 + 单调改进协议）

1. **spill 估计器数据驱动校准**：以全部 1300 项官方评估的
   `spill_added_copy_bytes` 真值为标签，对四路信号（L1/UB 池的
   区间峰值超限与内部总量超限）做 NNLS 拟合（80/20 留出）：
   系数 `[2.31·L1p + 0.86·L1w]`（UB 池≈0），
   spill 真值排序相关 场景A 0.335→0.681、场景B 0.569→0.747，
   留出集 R²=0.50。
2. **活体验证（10 用例×2 场景）**：校准模型端到端不稳定
   （Makespan 中位≈0%、均值 +4.3%，个别用例大幅波动）——
   排序改善≠最终方案改善，且搜索随机性是主要混杂。
   科学决策：校准模型不设为默认，改作**多样性种子**。
3. **单调改进协议**（`improve_runs.py`）：用校准模型 + 新种子重解全部
   800 任务；≤1.2 万 op 用 in-run 官方真值、大用例单独官方评估，
   与现有方案比较后**仅保留严格更优者**（`makespan + 0.2·added/60`
   标量化），被替换条目的官方结果全部重生成。结果：
   - 212 个小图 + 79 个大图 = **291/800 任务的方案被真值更优者替换**；
   - 平均加速比提升：P1 +2.2%/+3.1%/+2.8%/**+4.9%**（2→5 核），
     P2 +0.6%~+2.5%，P3 +0.5%~+2.5%；
   - 该协议在结构上保证结果**只升不降**（436 个任务保留原方案）。

## 6.1 技术升级轮（v3）：综述对标后的实现与实验

按 2024-2026 文献综述（`survey_gap_analysis.md`）对齐后实施，**全部经
真值 A/B 验证**，其中两项被数据否决（如实记录）：

| 项 | 设计 | 实验结果 | 决定 |
|---|---|---|---|
| op 级 LRU spill 仿真 | 复刻官方 step2 逐出语义，逐张量生命周期仿真 | 排序相关仅 **0.295**（32 个真值 spill>0 用例），远低于启发式+NNLS 的 0.75 | **回退**（默认关，保留开关） |
| overlap 因子（搬运/计算重叠折减） | 按子图依赖宽度估计重叠潜力 φ，未重叠搬运时间加回 | 100 用例排序相关不变（0.968=0.968），偏差 +2% | **默认关** |
| 大用例逐案真值在线校正 | 搜索中期 top-2 做进程内官方评估，比值作为 fitness 偏置再精搜 | 已实现（>1.2 万 op 任务自动触发） | 保留 |
| EFT 容量装箱 + M/V 互补分核 | 每核 L1/UB 预算 + 双管道失衡打分 + 输入通信计入 EFT | 互有胜负：case_011 −4%、case_002 −4.5%，case_004 +20% | 进构造池，交搜索+真值择优 |
| L2 双池代理（场景 C） | 跨核重复读首核付 DDR、其余按 250B/cy 独立池命中计；≤1MB 才命中 | 全链路通过（P3 求解不再盲跑） | 保留 |

**v3 keep-best 全量轮**：EFT 分核 + 真值校正 + 新种子重解 800 任务，
**116 小图 + 43 大图 = 159 个任务被真值更优者替换**（小图均值 −2.9%），
518 条官方结果重生成。最终加速比（对比 v2 轮）：P1 +0.8~+1.7%、
P2 +0.3~+0.9%、P3 +0.3~+0.8%。

**关键教训**（实验驱动的认知修正）：
1. 凝聚式切分（NetBenefit 合并）在块号与拓扑序交错的图上**无法保证拓扑凸**，
   区间夹块使簇商图成环，深图上反而比 heft 差 2.4 倍——heft 的
   路径式增长天然凸性，是深图的正确基元（与综述 LATTICE 结论一致）；
2. "更精确的仿真"不等于"更好的代理"：LRU 仿真低估了官方换入换出的
   级联效应（每次 spill 引发后续重读），启发式 + 真值校准更稳；
3. 收益递减规律：v2 轮替换 291/800（均值 −4.9%），v3 轮 159/800
   （均值 −2.9%）——多种子 keep-best 每轮仍有正收益但幅度减半，
   继续轮次的边际成本需权衡。

## 6.3 第五轮：实验可信性修复 + 问题三独立接通

### 6.3.1 可复现性基础设施（`solver/repro.py`）

- **稳定种子**：`crc32(case-scene-N-phase)` 替换进程随机化的 `hash()`——
  验收：删除方案重解，产出**字节级一致**的计划（哈希 139fd1a3… 复现成功）；
- **求解清单** `solve_manifest.jsonl`：每条记录种子/输入哈希/配置哈希/
  **代码版本（solver/*.py 内容哈希）**/方案哈希/耗时——任一变化即视为
  输入变更重新求解，命中即跳过（断点续跑不覆盖）；
- **评估清单** `eval_manifest.jsonl`：官方结果按"方案哈希"判失效，
  替换 mtime 逻辑；P1→A 方案、P2→B 方案、**P3→C 方案优先（回退 B）**；
- **单一数据源**：summary.csv / summary.md / appendix.md / plots 全部由
  `aggregate.py` 一次生成——验收：两次运行输出 `cmp` 字节级一致。

### 6.3.2 问题三独立优化与逐案裁决（`p3_decide.py`）

场景 C（L2 复用距离代理）独立求解全部 400 任务 → P3 官方评估对比
B 方案（同评估器）：

| 结果 | 数值 |
|---|---|
| C 方案全量平均 | **比 B 方案差 +5.15%**（均值）——L2 感知代理整体误导 |
| 逐案裁决 | C 胜 85（该子集 C 好 **−5.7%**）/ B 胜 166（C 差 +8.1%）/ 并列 149 |
| **最终 P3**（逐案保留更优） | 加速比 1.769 / 2.401 / **2.969 / 3.425**（2→5 核） |
| **L2 加速比** | **1.028 → 1.023 → 1.044 → 1.056**（单调随核数增长） |

诚实结论：L2 复用距离代理只在约两成用例上方向正确（宽复用图 + 高核数），
但该子集收益显著（最高 −12.5%）；逐案真值裁决既拿到了全部收益又规避了
代理误差——这正是"Evaluator 是 Judge"原则的又一次验证。
