# MCTS 修复版代表集实验

日期：2026-09-25

## 修复内容

- 将 PUCT 回传价值改为相对根节点的归一化收益，范围限制为 `[-1, 1]`。
- 使用 transposition table 共享重复状态统计。
- 增加最大代理评估数和停滞终止条件，避免状态空间耗尽后空转。
- 原有禁忌、退火、蚁群和 MOPSO 保留完整时间预算；MCTS 使用额外预算。
- MCTS 使用独立归档和 top-K 候选池，不修改或挤出原流程候选。
- 官方评估先核验原候选，再额外核验 MCTS 候选，并记录最终候选来源。

## 实验设置

固定 12 个代表算例、A/B 场景、2--5 核、seed=0、verify-k=24，
以 `plans_verify24_seed8_smoke` 强基线作为 warm start：

```cmd
.venv\Scripts\python.exe -m solver.run_all --cases 1,7,15,23,42,44,49,63,67,78,82,97 --cores 2,3,4,5 --scenes A,B --workers 8 --seed 0 --verify-k 24 --mcts --warm-start-dir results/plans_verify24_seed8_smoke --output-dir results/plans_mcts_fixed_trial --log-file results/solve_log_mcts_fixed_trial.jsonl
```

## MCTS 有效性

- 96/96 项实际执行 MCTS，0 个 `mcts_error`。
- 平均迭代 225 次，旧版约 121,298 次；平均评估 89.5 个唯一状态。
- 平均 MCTS 搜索耗时 1.35 秒，平均额外官方核验 6.86 个候选。
- 官方最终选择来源：MCTS 16 项、原流程 73 项、warm start 7 项。
- 19 个改善项中 16 个由 MCTS 直接产生；MCTS 对总体平均提升贡献约 +0.26128%。
- 最大单项改善为 `case_044 B/4` 的 +9.56884%。

## 结论

修复消除了旧版的 11 项退化，并把相对强基线的平均增量从 -0.23116%
提高到 +0.28566%。运行时间增幅 19.62%，满足不超过 25% 的约束；但平均
提升略低于预设的 +0.3% 全量门槛，因此暂不直接扩大到 800 项。建议下一步
针对 B/4、A/3、A/4 做一次小范围候选排序消融，确认收益稳定后再决定全量。
